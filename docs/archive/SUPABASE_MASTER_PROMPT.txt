PART 2: COMPLETE DATABASE SCHEMA
═══════════════════════════════════════════════════════════════════════════════

CORE TABLES (7 tables):

1. ORGANIZATIONS (Multi-tenant root - renamed from companies)
   - Purpose: Root of multi-tenant hierarchy
   - Fields:
     * id (UUID, primary key, auto-generated)
     * name (VARCHAR 255, NOT NULL, unique)
     * email (VARCHAR 255, NOT NULL, unique)
     * industry (VARCHAR 100)
     * website (VARCHAR 255)
     * country (VARCHAR 100, NOT NULL)
     * timezone (VARCHAR 50, default 'UTC')
     * active (BOOLEAN, default true)
     * subscription_tier (VARCHAR 50: 'free', 'starter', 'pro', 'enterprise')
     * subscription_start_date (TIMESTAMP)
     * subscription_end_date (TIMESTAMP)
     * max_users (INTEGER, based on tier)
     * features (JSONB, array of enabled features)
     * settings (JSONB, organization-wide settings)
     * billing_address (JSONB)
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Security: Admins only
   - Indexes: UNIQUE(name), UNIQUE(email), (active), (created_at DESC)

2. ROLES & PERMISSIONS (Define system roles once, reuse everywhere)
   - Purpose: Centralized role and permission definitions
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * name (VARCHAR 100, NOT NULL) - e.g., 'admin', 'manager', 'user', 'viewer'
     * display_name (VARCHAR 255)
     * description (TEXT)
     * permissions (JSONB array) - e.g., ['inventory.read', 'inventory.write', 'warehouse.admin']
     * priority (INTEGER) - for hierarchy
     * is_system_role (BOOLEAN) - cannot delete if true
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Unique: (organization_id, name)
   - Default System Roles:
     * admin: All permissions
     * manager: Operational permissions
     * user: Basic permissions
     * viewer: Read-only permissions
   - Security: Admins only

3. USERS (Application users linked to Supabase Auth)
   - Purpose: User profiles and authentication
   - Document ID: auth.uid() from Supabase Auth
   - Fields:
     * id (UUID, primary key, same as auth.uid())
     * organization_id (UUID, FK to organizations, NOT NULL)
     * email (VARCHAR 255, NOT NULL)
     * full_name (VARCHAR 255)
     * first_name (VARCHAR 100)
     * last_name (VARCHAR 100)
     * role_id (UUID, FK to roles, NOT NULL)
     * department (VARCHAR 100)
     * phone (VARCHAR 20)
     * avatar_url (VARCHAR 255)
     * active (BOOLEAN, default true)
     * last_login (TIMESTAMP)
     * last_activity (TIMESTAMP)
     * preferences (JSONB) - UI preferences, theme, etc.
     * metadata (JSONB) - custom user metadata
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Unique: (organization_id, email)
   - Indexes: (organization_id, active), (role_id), (created_at DESC)
   - Security: Users can view/edit own profile, admins manage all

4. WAREHOUSES (Physical locations)
   - Purpose: Storage locations for inventory
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * code (VARCHAR 50, NOT NULL) - e.g., 'WH-001'
     * name (VARCHAR 255, NOT NULL)
     * description (TEXT)
     * address (JSONB) - {street, city, state, zip, country}
     * location_coordinates (GEOMETRY/POINT) - for mapping
     * phone (VARCHAR 20)
     * email (VARCHAR 100)
     * manager_id (UUID, FK to users)
     * is_default (BOOLEAN, default false)
     * is_active (BOOLEAN, default true)
     * warehouse_type (VARCHAR 50) - 'distribution', 'storage', 'retail'
     * capacity (INTEGER) - total units
     * current_utilization (INTEGER)
     * utilization_percentage (NUMERIC, computed)
     * opening_hours (JSONB) - operation schedule
     * metadata (JSONB)
     * created_by (UUID, FK to users)
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Unique: (organization_id, code)
   - Indexes: (organization_id, is_active), (organization_id, created_at DESC)
   - Security: Members view, managers edit, admins delete

5. PRODUCTS (Product catalog)
   - Purpose: Product definitions and specifications
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * sku (VARCHAR 100, NOT NULL) - Stock Keeping Unit
     * name (VARCHAR 255, NOT NULL)
     * description (TEXT)
     * category (VARCHAR 100, NOT NULL)
     * subcategory (VARCHAR 100)
     * manufacturer (VARCHAR 255)
     * manufacturer_code (VARCHAR 100)
     * brand (VARCHAR 100)
     * pricing (JSONB) - {cost, retail_price, margin, currency}
     * dimensions (JSONB) - {length, width, height, unit}
     * weight (NUMERIC) - in kg
     * volume (NUMERIC) - in liters
     * barcode (VARCHAR 100)
     * qr_code (VARCHAR 255)
     * is_active (BOOLEAN, default true)
     * is_discontinued (BOOLEAN, default false)
     * is_hazardous (BOOLEAN, default false)
     * storage_requirements (JSONB) - temperature, humidity, etc.
     * tags (TEXT[]) - searchable tags
     * metadata (JSONB)
     * created_by (UUID, FK to users)
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Unique: (organization_id, sku)
   - Indexes: (organization_id, is_active), (organization_id, category), (sku), (barcode)
   - Security: Members view, managers edit, admins delete

6. INVENTORY (Stock levels by product and warehouse)
   - Purpose: Real-time stock tracking
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * product_id (UUID, FK to products, NOT NULL)
     * warehouse_id (UUID, FK to warehouses, NOT NULL)
     * quantity_on_hand (INTEGER) - physical stock
     * quantity_reserved (INTEGER) - allocated to orders
     * quantity_damaged (INTEGER) - unusable
     * quantity_available (INTEGER) - COMPUTED: quantity_on_hand - quantity_reserved
     * quantity_on_order (INTEGER) - incoming
     * reorder_point (INTEGER) - when to trigger reorder
     * reorder_quantity (INTEGER) - how much to order
     * lead_time_days (INTEGER) - supplier lead time
     * turnover_rate (NUMERIC) - calculated from movements
     * safety_stock_days (INTEGER)
     * last_counted (TIMESTAMP) - last physical count
     * last_restocked (TIMESTAMP)
     * last_sold (TIMESTAMP)
     * expiration_date (TIMESTAMP) - for perishables
     * batch_number (VARCHAR 100)
     * location_in_warehouse (VARCHAR 255) - aisle/shelf/bin
     * is_active (BOOLEAN, default true)
     * metadata (JSONB)
     * created_at (TIMESTAMP)
     * updated_at (TIMESTAMP)
   - Unique: (organization_id, product_id, warehouse_id)
   - Indexes:
     * (organization_id, warehouse_id, quantity_available)
     * (organization_id, product_id)
     * (warehouse_id, product_id)
     * (organization_id, updated_at DESC)
     * Low stock: WHERE quantity_available <= reorder_point
   - Security: Members view, managers edit

7. STOCK_MOVEMENTS (Immutable audit trail)
   - Purpose: Log every inventory change
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * inventory_id (UUID, FK to inventory, NOT NULL)
     * product_id (UUID, FK to products, NOT NULL)
     * warehouse_id (UUID, FK to warehouses, NOT NULL)
     * movement_type (VARCHAR 50, NOT NULL) - 'add', 'remove', 'adjust', 'transfer_in', 'transfer_out', 'count', 'damage', 'return'
     * quantity_before (INTEGER)
     * quantity_after (INTEGER)
     * quantity_changed (INTEGER)
     * reason (VARCHAR 100) - 'purchase_order', 'sales_order', 'physical_count', 'adjustment', etc.
     * reference_number (VARCHAR 100) - PO#, SO#, etc.
     * notes (TEXT)
     * from_warehouse_id (UUID, FK to warehouses) - for transfers
     * to_warehouse_id (UUID, FK to warehouses) - for transfers
     * initiated_by_user_id (UUID, FK to users)
     * approved_by_user_id (UUID, FK to users)
     * approval_timestamp (TIMESTAMP)
     * document_url (VARCHAR 255)
     * cost_impact (NUMERIC) - financial impact
     * created_by (UUID, FK to users, NOT NULL)
     * created_at (TIMESTAMP, NOT NULL)
     * batch_id (UUID) - group related movements
   - Indexes: (organization_id, created_at DESC), (warehouse_id, created_at DESC), (product_id, created_at DESC), (batch_id)
   - CONSTRAINTS:
     * IMMUTABLE: No updates or deletes allowed
     * CHECK: quantity_changed = quantity_after - quantity_before
   - Security: Members view, system creates, no updates/deletes

8. AUDIT_LOGS (System audit trail)
   - Purpose: Compliance and debugging
   - Fields:
     * id (UUID, primary key)
     * organization_id (UUID, FK to organizations, NOT NULL)
     * user_id (UUID, FK to users)
     * action (VARCHAR 50) - 'create', 'read', 'update', 'delete', 'export', 'import'
     * resource_type (VARCHAR 100) - 'inventory', 'warehouse', 'product', 'user', 'order'
     * resource_id (UUID)
     * resource_name (VARCHAR 255)
     * old_values (JSONB) - before state
     * new_values (JSONB) - after state
     * changes (JSONB) - only changed fields
     * status (VARCHAR 50) - 'success', 'failure'
     * error_message (TEXT)
     * ip_address (INET)
     * user_agent (TEXT)
     * session_id (VARCHAR 255)
     * request_id (VARCHAR 255)
     * created_at (TIMESTAMP, NOT NULL)
   - Indexes: (organization_id, created_at DESC), (user_id, created_at DESC), (resource_type, resource_id)
   - CONSTRAINTS:
     * IMMUTABLE: No updates or deletes allowed
   - Security: Members view, system creates, no updates/deletes

PART 4: ROW LEVEL SECURITY (RLS) POLICIES
═══════════════════════════════════════════════════════════════════════════════

FUNDAMENTAL PRINCIPLE: No user can see data outside their organization.

HELPER FUNCTIONS:
1. auth_organization_id() - Get user's organization_id
2. auth_user_role() - Get user's role
3. auth_has_permission(permission) - Check if user has permission
4. auth_user_id() - Get current user ID

POLICY PATTERNS:

ORGANIZATIONS TABLE:
- SELECT: Only admins of own org
- INSERT: Not allowed (admins only)
- UPDATE: Only admins
- DELETE: Not allowed (admins only)

USERS TABLE:
- SELECT: Users of same org (restricted fields for non-admin)
- INSERT: Admins only
- UPDATE: Admins + user can update own profile
- DELETE: Admins only

ROLES TABLE:
- SELECT: Members of same org
- INSERT: Admins only
- UPDATE: Admins only
- DELETE: Admins only (except system roles)

WAREHOUSES TABLE:
- SELECT: Members of same org
- INSERT: Managers and admins
- UPDATE: Managers and admins
- DELETE: Admins only

PRODUCTS TABLE:
- SELECT: Members of same org
- INSERT: Managers and admins
- UPDATE: Managers and admins
- DELETE: Admins only

INVENTORY TABLE:
- SELECT: Members of same org
- INSERT: Members can add
- UPDATE: Managers and admins
- DELETE: Admins only

STOCK_MOVEMENTS TABLE:
- SELECT: Members of same org
- INSERT: System only (via triggers)
- UPDATE: NEVER (immutable)
- DELETE: NEVER (immutable)

AUDIT_LOGS TABLE:
- SELECT: Members of same org (limited fields)
- INSERT: System only (via triggers)
- UPDATE: NEVER (immutable)
- DELETE: NEVER (immutable)
